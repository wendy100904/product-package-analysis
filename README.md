# B 端招聘平台用户分层与产品偏好分析

> 无监督用户分群（K-Means）+ 产品关联规则挖掘（支持度 / 置信度 / 提升度）+ 用户标签体系 + 行为路径模式挖掘的完整数据科学项目。
> 面向 B 端招聘 SaaS 的存量用户运营场景，从"发现问题 → 特征工程 → 建模选型 → 业务落地"给出闭环方案。

---

## 一、项目背景与业务痛点

某 B 端招聘平台拥有大量企业侧付费/权益用户，但运营长期面临三个问题：

1. **用户千人一面**：缺乏可运营的分层，高价值客户与流失风险客户被同等对待。
2. **产品交叉销售无抓手**：不清楚哪些产品组合天然互补，推荐全凭经验。
3. **行为链路是黑盒**：不知道用户在平台内的典型使用路径，无法针对性做引导。

本项目用一套可复现的分析管线回答上述问题，并直接产出可落地的运营建议。

## 二、分析与建模思路

```
数据加载 → 数据预处理 → 特征工程(RFM+行为+属性) → K-Means 用户分群(肘部法则自动选 K)
        → 聚类画像分析 → 用户标签体系 → 产品关联规则(Apriori 思想) → 分群产品偏好 → 行为路径挖掘
```

| 环节 | 方法 | 说明 |
|---|---|---|
| 特征工程 | RFM + 使用强度 + 产品多样性 + 活跃度评分 | 按用户维度聚合，避免行级重复计算 |
| 用户分层 | K-Means + 肘部法则(二阶差分自动定 K) + PCA 可视化 | 标准化后聚类，兼顾可解释性 |
| 关联分析 | 共现统计 + 支持度/置信度/提升度 | 挖掘产品交叉销售机会（Apriori 思想的轻量实现） |
| 标签体系 | 聚类标签 + 规则型业务标签 | 客户属性/城市/行业/薪资/活跃度多维打标 |
| 路径挖掘 | 序列子串频次 + 用户覆盖率 | 长度 ≥3 的高频行为路径 |

## 三、核心发现与落地建议（示例，基于脱敏数据）

- **分群结果**：用户可自动聚为若干群体，如「超级活跃权益型」「高频新职位活跃型」「低频付费型」等，规模与画像差异显著。
- **关联规则**：识别出提升度 >1 的产品组合，可据此做**产品捆绑**与**界面自动推荐**。
- **落地 SOP**：
  - 高价值活跃群 → 专属权益 + 续费提醒；
  - 低频付费群 → 使用引导 + 交叉推荐互补产品；
  - 长期未活跃群 → 召回触达。

> 报告中的绝对数值（GMV、消耗金额等）已做脱敏处理，仅保留趋势与占比。详见 [`report/`](./report)。

## 五、快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 生成脱敏示例数据
python src/data/generate_sample_data.py

# 3. 运行完整分析管线
python main.py

# （可选）单独运行行为路径挖掘
python src/path_analysis.py
```

> 生产环境可通过环境变量切换数据源：`export SOURCE_TABLE=your_table` / `export ANALYTICS_DATA_PATH=your.csv`。

## 六、数据安全与合规（Data Privacy & Compliance）

本项目代码与可视化报告仅作为个人数据分析、算法建模（K-Means / 关联规则）及业务落地方案的**逻辑展示**。出于数据安全与商业保密协议（NDA）要求，原始生产环境数据集已作留存隔离，仓库内提供**模拟示例数据（Synthetic Sample Data）**用于代码逻辑复现。

已完成的脱敏处理：

- **字段去标识化**：内部数据字典字段名（如原始 ID、日志日期前缀、业务缩写字段）已统一重命名为行业通用术语（`user_id` / `event_date` / `product_type` 等）。
- **连接信息清除**：不含任何真实数据库连接串、IP、账号密码；生产表名统一由环境变量注入。
- **主体代号化**：企业、城市等真实主体以代号呈现（`Company_*` / `City_Tier_*`）。
- **指标脱敏**：报告中敏感绝对数值按固定系数处理，仅保留趋势与占比，不涉及原公司任何未公开商业机密。
